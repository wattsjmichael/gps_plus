# v0.4.0 validation and startup investigation

## Cause identified before implementation

- Public setup wrote `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\ForeverVoice Helper.cmd`.
  Windows executes that batch file through a console, even though build-setup.ps1
  already used `--noconsole` for the public helper.
- Development install.ps1 wrote `ForeverVoice Helper.lnk`. For a packaged helper it
  targeted the EXE built by build-helper.ps1 with `--console`; for source it targeted
  hidden PowerShell, which invoked console `python.exe`.
- The exact active entry on the user's PC could not be inspected from this Linux
  environment. These are the two startup mechanisms evidenced by repository code.

Both installers now configure a single per-user Run entry. Source launch uses
pythonw.exe; both packaged builds use --noconsole. Known legacy entries migrate
when the new helper first starts. Install/update and uninstall remove legacy entries.
Other startup entries are left alone. The installer still stops older packaged
helpers using its preexisting taskkill path during update/uninstall; tray Exit does
not use that path and never scans/kills unrelated processes.

## Automated validation (Linux, no WoW)

Run `python -m unittest discover -s ForeverVoice/tests -v` from the repository root.
Eleven tests cover a real competing-process lock/recovery, registry command quoting
and legacy cleanup with a mocked Windows registry, controller channels and shutdown
guards, model failure reporting, microphone capture failure cleanup, and isolated
microphone-test transcription with mocked hardware/model. Python compileall and
`git diff --check` pass. A dependency-free Python wheel build also passes
and includes all three helper modules. Hardware, GUI, and Windows build behavior are not verified by
these tests. The addon Lua and HUD protocol have no behavior changes.

## Windows manual verification still required

1. Build with build-helper.ps1 and build-setup.ps1; verify both EXEs open without a
   console, with the tray icon visible. Test a source launch through run-helper.ps1.
2. Update an existing installation with its `.cmd` or `.lnk` present. Inspect the Run
   value and confirm both old entries are removed. Sign out/in: one helper, no console.
3. Toggle Start with Windows on/off in the tray. Confirm the Run value and behavior
   at next sign-in, including installation paths containing spaces.
4. Launch twice (including a source/frozen pair). Verify one recorder/model instance
   and the existing diagnostics window opens. Exit and verify relaunch works.
5. With WoW closed, check microphone name, Whisper Loading/Ready/Failed, controller
   connect/disconnect (slot 0), and WoW Not running. Deny microphone permission,
   disconnect it, or use an unavailable saved device; the window must stay usable.
6. Test Microphone: speak for three seconds and verify displayed text, no keystrokes.
   Repeated clicks while busy must not start overlapping capture. Check error logs.
7. Exit while idle, recording, testing, loading a model, and transcribing. Verify
   audio closes, workers finish, and the packaged parent/child processes disappear.
   A model download/inference may take time; Exit waits instead of abandoning workers.
8. Once WoW is available, verify existing bindings/channel slots, custom saved
   bindings, HUD recording/transcribing/idle states, focus protection, and delivery.
   In-game integration has **not** been verified.

No release, tag, installer binary, or published asset was created.
